Recon and decomposition

complete

11 agents · 1,548,031 tokens · 23 pieces produced

Six readers mapped the editor UI, the effect pipeline, the move and status data, the DECK_SIZE invariant, the Realm Deck and the test harness. A lead decomposed the goal; three critics attacked the decomposition and the lead revised it.

What it turned up

  • Every editor-layout change is a LIVE-DATA change. captureEditorIntoCard reads the DOM with num(id,min,max,fallback) and 77 of those pass a literal fallback — remove a field from the DOM and the number is silently rewritten to a constant, then cloud-pushed to every owner. npm run check sees none of it.
  • The editor is 900px wide on every monitor. .card-editor{max-width:900px} at index.html:33891 still applies to .card-editor.fx-two — 343 fields in a two-column grid inside ~500px. The sprawl is one declaration.
  • Effect (c) has no event to fire on. There is exactly one void→deck movement in the engine, inside shuffleToDeck at index.html:111991, and its zone default was moved off void after an earlier hand-wipe bug. The trigger needs the effect built first or it can never fire.
  • renderForge is admin-gated and bounces silently. Every screenshot bar in the first plan would have photographed the title screen and reported success.

Live save-path bugfix

complete

3 agents · 498,277 tokens

The contract net found three defects that are corrupting real cards right now, and index.html was otherwise idle. Fixing the spell second-element loss, the minCost clobber, and the class of round-trip data loss behind the 74 unrenderable paths. Governing rule: saving a card without touching anything must never change it.

pieceverdictwhat came back
live save-path defectsfixed, verifiedTwo-element spells kept both elements (was dropping to one). vanishUnit minCost stays 5 (was forced to 0). Void-ability card filters and hand-authored onResurrect blocks survive a reopen. Unrenderable-but-written field paths went 74 to 0. Each proved by running the same check against the pre-change build first.

What it turned up

  • The onResurrect bug was two stacked. The Auto-copy checkbox rendered checked for any card that merely HAD a resurrect block, so a deliberately different one was overwritten by a copy of on-play. Un-checking it alone would have been worse — one edit to on-play would have permanently diverged the card and silently stopped the mirror. The intent is now a flag and the copy runs last.
  • The mirror also ran about 380 lines BEFORE on-play was read, so it was copying the previous save.
  • The codebase already had the right idiom for this whole class — num(id, min, max, card.stats.hp || 20), preserve rather than re-read. The fix extends that rather than inventing a pattern.

The remodel begins — width, then gating

complete

13 agents · 2,863,303 tokens

Editor width first: .card-editor{max-width:900px} still applies to the two-column layout, so the editor is 900px on every monitor — a 380px asset rail plus about 500px holding 343 fields at roughly 230px per column. That one declaration is the sprawl. Then per-effect field gating: 21 pickers labelled "(when effect is X)" currently render for every effect, across the primary block, five sibling blocks and six extra slots. Both judged against a legibility floor so density cannot be bought by shrinking the type, and both gated on the 153-card round trip.

editor-widthpass, 2 roundsAt 1600px the editor went 900px to 1549px and the properties column 22,109px to 14,876px — down 32.7%. Grid columns 2 (min 181px) to 3-4 (min 268px). Labels wrapping past two lines: 44 to 0. Controls under 28px tall: 38 to 0. Move editor and event editor still 900px, untouched.
effect-field-gatingpass, 2 roundsAcross all 118 effect types the on-play block now shows only the fields that effect actually reads, checked against a whitelist computed independently from the save path. Hidden fields stay in the DOM, and the change handler re-runs the empty-section sweep and the nav-chip hider.
data-backup-exporthole closedThe refusal moved into one resolve pass that every entry point inherits, including memoryStore — the one the migrations will actually call.

What it turned up

  • The 32.7% is layout, not hiding. The panel text content is byte-identical before and after — same hash, same 290 fields, same font histogram at all four widths — so density was not bought by shrinking type.
  • grid-auto-flow:dense was rejected on purpose. It bought another 375px but reorders fields on screen while tab order stays in DOM order, and a card editor whose fields move about is a worse bug than a taller one. The reasoning is in the code.
  • A critic caught an undisclosed phone regression: the new sub-grid rule outranks the editor's own single-column rule below 600px, so a 340px track overflowed a narrower viewport. Fixed with min(340px,100%) and verified.

Two reported bugs, then ship

complete

Paused the remodel to fix two things the owner reported: the City Builder Treasury chip flicking between two numbers, and the Containment Lab being unable to produce a working cure. Both fixed, tested and shipped together with everything the run had completed, as v121v77.

pieceverdictwhat came back
cinder rate chipfixed, liveBoth numbers were real. Rent is continuous, patronage is not — so the old line booked each lump as an instantaneous rate (x60) and contributed nothing in between. On a city truly making 18/min it printed 180, then 0, then 180. Now averaged over whole closed minutes, which is piecewise constant rather than merely damped, plus a band so the chip does not chase noise below its own precision.
containment lab curesfixed, liveThree defects at once. The blend is a weighted average, so every mix lands inside the convex hull of the reagents — and the 13 shipped reagents had no vertex in four corners the strain generator produces, making 7.8% of strains uncurable however well played. Twelve reagents added from the 142 the game now has: 7.8% to 0.8%. The SUGGEST button was a per-axis greedy that reached broad-spectrum 0.0% of the time and produced something worse than a cure 19.5% of the time; it is now a real solver that plans inside the player stock and reaches viable-or-better 100%. And every jar now shows what one more unit does to the vessel in front of you, ordered by what helps most.

What it turned up

  • The cures file was built against "RESOURCES (14 entries)". It has 142. Medicine was being made out of wood, stone and cloth while the player's warehouse held acids, solvents, silica, herbs and medical chemicals — which is exactly what the owner said.
  • The first fix for the flicker was rejected by its own test: a decaying average still rippled 21.8 to 18.5 at one lump a minute, which on a one-decimal chip is still a number changing every second.
  • The deploy gate failed in a way that looked unrelated — three headless suites dying on "Execution context was destroyed". Cause: BUILD_VERSION was bumped but version.txt was not, so the app's own update-check decided a newer build was live and reloaded the page 500ms into every test. Recorded, and the handoff's advice on that corrected.
