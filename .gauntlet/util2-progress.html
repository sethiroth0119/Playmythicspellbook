🧟 The outbreak is unfinished and untuned — and it can fire

Say it in those words, because a half-built outbreak that can fire is worse than no outbreak at all. This is the state it is in right now, in the working tree:

It is live. /src/zombie mounts from node-city's frame loop (public/node-city/index.html:40383, _zombieTick) and arms itself whenever /src/mortality is present — which is every city, because deathcare shipped in the same run. There is no kill switch and no config flag. grep for enabled or disable across public/src/zombie/*.js returns nothing.

It destroys real buildings. A breached wave calls ctx.damageTile(pick, st.destroy, '💥 The outbreak') up to maxStrikes: 4 times, and above razeRatio: 2.5 the strike destroys rather than damages. That funnel is deliberately the only write path (criterion 5 held), but it is still a live demolition path that has never been played.

It has never been tuned by a human. Every number in public/src/zombie/tuning.js — arm: 60, interval: 1800, pMax: 0.55, strPerBody: 2.4, deadCapFrac: 0.05 — was chosen to make the model coherent, not because anyone sat with a city and felt it. Whether the first outbreak lands as a fair consequence or as an unexplained mugging is completely unknown.

There are no zombies. No agent is spawned, no mesh, no scene handle. The whole feature is a number, a card, a log line and some damaged tiles. risk.js:22-30 states this plainly as a deliberate deferral (no infection state machine, no district spread, no walking horde) and that block is honest — but a player who reads "OUTBREAK LIKELY" and then sees nothing walk is going to expect something the game does not have.

And the round-3 gap is still open. When you build the graveyard that fixes it, the card does not tell you it worked — see the piece below. So the one loop that would let a player learn the system by playing it is the loop that is missing.

Read this second: what is not done, what was cut

Everything below was scored against a written bar. Passing a bar is not the same as finished, and it is nowhere near the same as played. No human has touched any of this. Every proof in this log came from a driven browser or a node harness. Nothing is committed, nothing is deployed, no version knob was bumped, and no migration was run.

Not done

  • The outbreak's feedback loop. Round 3's gap is open: build burial capacity and the meter does not visibly move, so the game never confirms your fix.
  • No infection state, no spread, no horde. Deliberate and written down (risk.js:14-30), but it means the outbreak is an event, not a system.
  • Nothing is persisted server-side. No table, no RLS, no migration — all of this run's state rides MythicCitySave in the local save blob.
  • No pixel measurement was re-run for this page. The A/B deltas and controls quoted in the round rows come from the round transcripts. This write-up re-ran the three gates only. Treat every pixel number here as reported, not reproduced.

Cut on purpose

  • The Lane (roadlane) is retired. Round 1 caught it orphaned — deleted from the shop, never re-homed, still promised by research. It was not rescued; it was deliberately retired: retired: true at index.html:3074, dropped from tra_basic's unlocks (progression/tree.js:84). Old saves with Lane tiles still load and still render — the BUILDINGS row and isRoadType were kept for exactly that — but nobody can ever lay another one.
  • No second waterline, no third opinion. The resource map refuses and records stats.refused when MythicWater is absent rather than inventing a field. Delete the module and production is byte-identical.
  • No new UI for the deathcare complaint. It rides the existing vitals card, talk dialog and phone feed. That was the bar, and it means the shortfall is easy to miss if you are not looking.

A human must verify by playing

  • Play until an outbreak fires. Nothing else on this list matters as much. All outbreak evidence is simulated time in a headless harness. Confirm the first one lands inside the window the card promised, and that losing a building to it reads as a consequence you could have prevented.
  • Look for a road in the build tab and fail. Roads left BUILD entirely. Whether a player's hand goes to the 🛣 Roads tab without being told is a question only a person can answer.
  • Load an old save with Lane tiles. Confirm the retired carriageway reads as legacy, not as a bug.
  • Find the sea drain. It may only stand in open water. Does anyone discover that rule without reading the refusal message twice?
  • Read the resource map at real zoom on a real monitor. Determinism and threshold agreement are proven; legibility is not.
  • The 15th rail launcher. The outbreak card took a seat the RAILS comment said was the last one. Check the rail does not overflow at your window size.
