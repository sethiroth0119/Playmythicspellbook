# 🏷 Business names, and what the city save actually contains

This is the note the save's own `meta.doc` field points at. It exists because
the cloud half is being wired by someone else — "I will add all this when we
are done here and ready for the hand over" — and that person needs to be able
to look at one payload and know what is in it without reading 24,000 lines.

---

## 1. What shipped

**Every building in the city has a name.** Not just operations — every shop,
foundry, farm, clinic, apartment block and public garden. Names are generated
offline, seeded off the tile, de-duplicated inside the city, shown in the
dossier header, editable inline, and saved.

The resolution order is the whole design, and it is deliberately **one**
concept rather than two:

| # | Source | Persisted? |
|---|--------|-----------|
| 1 | A name the player typed on this tile | yes, in `ext.names.n` + listed in `ext.names.c` |
| 2 | The **operation licence label** from City Hall (`corp_operations`) | no — it belongs to the game, not the city save |
| 3 | A generated name, seeded off the tile coordinates | yes, pinned on first use |

Row 2 is the case that already worked before this batch: `openInspect` read
`opsRowForKey(k).label` for a sited operation and its own comment said why
("`def.name` is the blueprint; the player named this one"). The register keeps
that exactly as it was and simply makes it the middle rung of a ladder, so
there is one naming idea in the codebase instead of two that disagree.

### Files

```
public/src/naming/words.js      the corpora + one trade-noun row per placeable
public/src/naming/generate.js   FNV-1a + mulberry32 + the pattern grammar
public/src/naming/registry.js   the register: resolve, sanitise, de-dupe, save
public/src/naming/address.js    house number + street, DERIVED, never stored
public/src/naming/save.js       SaveShelf — the module save shelf (below)
public/src/naming/index.js      mount(): window.MythicNaming + MythicCitySave
```

### Public API

```js
window.MythicNaming.nameFor(key)     // "Annu's Interior Design" | null for a road
window.MythicNaming.autoFor(key)     // the generated name, ignoring any override
window.MythicNaming.isCustom(key)    // did the player type this one?
window.MythicNaming.setName(key, s)  // sanitises, stores, saves, repaints
window.MythicNaming.clearName(key)   // back to the generated name
window.MythicNaming.address(key)     // { num, street, full } | null
window.MythicNaming.all()            // { "x,z": {name, custom, type, address} }
window.MythicNaming.stats()
```

Also on the diagnostics seam as `__nc.naming()` and `__nc.saveExt()`.

## 2. The module save shelf — read this before adding another save field

`serialize()` is a single object literal in a file three workflows edit at
once, and its own comments record the same failure three separate times:
a field that did not make it into that literal was a **silent** loss of player
data. So this batch adds **one** field, `ext`, and a registry behind it:

```js
window.MythicCitySave.register('streets', {
  save: () => ({ … }),        // whatever your module owns
  load: (payload) => { … },   // payload is undefined on an old save
});
```

That is all. No edit to `serialize()`, no edit to `loadState()`, and the next
feature's persistence is a non-event.

Three properties worth knowing:

* **Load order does not matter.** `loadState()` calls `restore(s.ext)`, which
  stashes the payload; a module that registers later is replayed immediately.
* **A missing module does not erase its data.** `collect()` writes back any
  stashed slice whose owner is not currently registered. A build where
  `/src/streets/` 404s round-trips a save without deleting the street names.
* **A throwing module costs only itself.** `save()` and `load()` are each in
  their own try/catch and its previous slice is preserved.

### `meta` — the self-describing header

`meta` is generated by *walking* the payload, not by listing keys by hand, so a
field somebody adds to `serialize()` next week is described automatically:

```json
{ "app": "node-city", "schema": 5, "ext": 1, "wrote": 1786997140280,
  "build": "v120i2-city",
  "keys": ["age","army","cits","deck","ext","fin","hunger","life","log",
           "morale","nodeXp","npcPop","raid","ramp","savedAt","stock",
           "syncPct","tiles","v","vitals"],
  "modules": ["names"], "tiles": 176, "doc": "/src/naming/HANDOVER.md" }
```

`schema` is the city save's own `v`, read off the payload rather than
duplicated — one place to bump.

## 3. Do I need a Supabase migration? **No.**

The city save is already `public.city_state (user_id uuid primary key, state
jsonb, …)`, one row per user, owner-only RLS
(`using (auth.uid() = user_id) with check (auth.uid() = user_id)`) — see
`city_state.sql`. Business names ride **inside** `state`, so the cloud half is
already done: `MythicCityBridge.saveCity(serialize())` writes them today.

No numbered migration was written, deliberately. A `city_businesses` table
would only be justified if names have to be **queried from outside the owner's
own save** — a neighbour-city view that lists shops, a world directory, a
search. None of those exist. Adding an unused table with its own RLS surface
is a security boundary to maintain for no feature.

⚠ **If names ever do become visible to another player, the sanitiser in this
module is not sufficient and must not be treated as if it were.** It strips
angle brackets, control characters and bidi overrides, and every render escapes
— that is an *injection* defence, not a *moderation* one. There is no profanity
filter here on purpose: CLAUDE.md is explicit that world chat's masking and
rate limiting moved into the `chat_send()` RPC and that client-side copies are
never enforcement. Public business names need the same treatment — a
`SECURITY DEFINER` RPC that cleans and rate-limits server-side — and it should
be written then, not faked now.

## 4. Size

Measured in the real browser on the standard Gauntlet district
(`.gauntlet/scene.js`, 179 tiles placed, 176 serialised, 76 of them nameable —
roads, walls, gates and anchors are not premises and carry no name):

| | bytes |
|---|---|
| save before this work | 27,569 |
| save after | 30,000 – 30,019 |
| **growth** | **+2,431 – 2,450 (+8.8 – 8.9 %)** |
| ├ `ext.names` | 2,094 – 2,113 |
| └ `meta` | 306 |

(The few-byte spread across runs is the per-city salt drawing longer or shorter
names — the same city always writes the same bytes.)

**≈28 bytes per named building.** A maximal 24×24 grid with every tile built
and none of it road would be ~576 names ≈ 16 KB — still an order of magnitude
under a localStorage budget, and the register prunes names for demolished tiles
on every write so the payload cannot grow without bound.

Addresses are **not** in that number and never will be: they are recomputed
from the road grid on read. Freezing them would be another ~5 KB of data that
is a pure function of state already saved, and it would go stale the first time
a player renamed a street.

## 5. The persistence audit

What `serialize()` / `loadState()` carried before this work, what this work
added, and what is still on the floor.

### Saved — top level

| Field | What |
|---|---|
| `v` | save schema (5) |
| `tiles` | every tile (below) |
| `raid` | countdown + wave + the interval it was written under |
| `army` | workers, soldiers, rank |
| `deck` | defense deck |
| `nodeXp` | per-node XP |
| `log` | the city log ring |
| `morale`, `hunger` | wellbeing |
| `stock` | refined-goods stockpile |
| `npcPop` | the soft citizenry |
| `vitals` | the six vital signs |
| `ramp` | grace already spent (an unsaved ramp is a refresh exploit) |
| `age` | the simulated city clock the `born` stamps are measured against |
| `cits` | the named citizen roster |
| `life` | the life log |
| `fin` | the investment book + last statement |
| `syncPct`, `savedAt` | node sync, and the offline-catch-up watermark |
| **`ext`** | **NEW — every module-owned slice. `names` today.** |
| **`meta`** | **NEW — the self-describing header above.** |

### Saved — per tile

`type`, `lvl`, `dmg`, `rot`, `card`, `cards`, `tenant`, `wear`, `born`,
`spent`, `earn`, `house` (Resting House billets + uncollected Resonance),
`stad` (Stadium history + append-only event ledger).

### NOT saved, and why

| State | Status | Note |
|---|---|---|
| **Business names** | ~~gap~~ **closed by this work** | `ext.names` |
| **Addresses** | derived by design | recomputed from the road grid on read |
| **Street names** | not yet built | `/src/streets/` — a slot in `ext` is waiting |
| **Zone types** | not yet built | `/src/zoning/` — same |
| **Transit lines** | not yet built | same |
| `game.expedition` | ⚠ **real gap** | an expedition in flight is lost on reload, along with the 2 soldiers and the equipped card. Not closed here because its timer is `performance.now()`-based and persisting it needs a wall-clock migration plus a decision about what happens to an expedition that "landed" while the tab was shut — that is a gameplay call, not a serialisation one. |
| `game.caravan` | minor gap | in-flight caravan trips vanish; the next one is scheduled 45 s after boot anyway |
| `game.frac` | intentional | sub-unit resource remainders; rounding error, not state |
| `game.res`, `game.wallet` | intentional | mirrors of the game's own ledger. Saving them would let a corrupt city save mint currency. |
| `game.cov`, `game.power`, `prodPerMin`, `t.svcFed` | intentional | all derived, recomputed on the first tick |
| `gov`, `events.rush` | intentional | server-owned (`loadGov`, `fetchEvents`) |
| `agents` | intentional | traffic and pedestrians are respawned by `manageAgents()` |
| camera, zoom, `QUALITY`, `mode`, `placeType`, `placeRot` | intentional | view/tool state, not city state |
| `MODEL_REGISTRY`, ops mock, mayor mock | separate localStorage keys | not part of the city payload |

## 6. Compatibility

* **An old save opens.** `ext` and `meta` are absent on every save written
  before this shipped; `restore(undefined)` is a no-op and the register fills
  the city with generated names. Driven in the harness: a payload with `ext`
  and `meta` deleted loads with all 179 tiles and all 76 names.
* **A new save opens in an old build.** Both new keys are ignored by any reader
  that does not look for them.
* **A build where `/src/naming/` 404s** writes a save with neither key,
  restores nothing, and loses nothing else. The dossier shows the blueprint
  name exactly as it did before.
* **Names are stable.** Driven: rebuilding the entire register from an empty
  cache reproduces all 76 names with zero drift, and so does a round trip
  through `save()` / `load()`.
